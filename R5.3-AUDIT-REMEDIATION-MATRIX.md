# R5.3 Audit Remediation Matrix

This release treats the SQL Hedge ledger as the production fact authority and the
native Freqtrade Trade/Order model as a compatibility projection only.  The old R5
CLI remains readable for historical evidence but refuses every exchange-write stage.

## P2

P2 items are treated as maintainability/governance work after the correctness boundary:
contract adapters freeze DTO conversion, credential ACL is enforced for writes,
direction-aware price normalization is present, config/authority manifests are added,
and the release records upstream/version evidence. A baseline migration squash and a
large-file refactor are intentionally not performed in the same release as the
execution-authority rewrite because they would enlarge migration and review risk.


## Position adoption and bootstrap invariant

A live position is never inferred as managed from symbol alone.  R5.3 requires a signed
adoption manifest with independent operator and risk tokens.  Successful adoption seeds
both the SQL execution position projection and the Core/Tactical inventory before any
reduce-only fill can be applied.  A bare `--adopt-position-leg` flag cannot create
authority.

## Production evidence maturity

- Module implementation: COMPLETE for the R5.3 authority graph.
- Offline integration: COMPLETE for Fake execution, recovery, fills, income, budget,
  fencing, ownership and schema.
- Protected mainnet evidence: available as GET-only audit, writes locked.
- Mainnet write evidence: NOT produced by installation and requires explicit marked
  credentials, strict key policy, signed adoption, independent stage permit and operator
  confirmation.
- 24/72-hour unattended evidence: PENDING elapsed operational observation; never
  synthesized by tests.
