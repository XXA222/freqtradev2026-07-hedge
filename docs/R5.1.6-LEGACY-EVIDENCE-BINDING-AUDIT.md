# R5.1.6 Legacy Evidence Binding Audit

## Root cause

R2.4.1 collected `/fapi/v3/account` and used `account.get("accountAlias", "unknown")`.
R5.1.5 incorrectly made `accountAlias` mandatory even though Binance can omit it.
This broke the compatibility proof before any read-only evidence could be recorded.

## Corrected contract

1. The API key and secret remain the cryptographic root of identity.
2. If `accountAlias` exists, R5 computes the live-alias R2.4 candidate.
3. R5 always computes the exact R2.4 missing-alias candidate using `unknown`.
4. The accepted R2.4 fingerprint must match one of those HMAC candidates.
5. The R2.5 stream fingerprint must match the same accepted R2.4 fingerprint.
6. Acceptance records the matched binding mode and rejects unbound evidence.

## Safety

The fallback is not a string-only identity. It remains HMAC-bound to the current
API key and secret. Missing aliases therefore do not weaken credential binding.
Order endpoints remain absent from the R5.1 read-only surface.
