# R5.3 Authoritative Execution and Fill Closure

## Release objective

R5.3 removes the split between the strategy plan and the production execution fact
source.  The SQL Hedge ledger is authoritative for order lifecycle, idempotency,
ownership, risk approval, audit, outbox, fills, income and daily budgets.  Native
Freqtrade Trade/Order rows remain read-only compatibility projections.

## Execution closure

The runtime accepts the complete R4 `PlanningResult`: risk cancellations, ordinary
cancellations, modify/delete replacement cancellations and submissions.  It executes
risk reduction first, approves the complete pending-risk batch against cumulative
portfolio state, reserves the complete daily budget before the first exchange write,
and rechecks the exact single-writer fencing token at the last network boundary.

A network result is projected through one post-network transaction containing the
latest order state, Intent, Fill, Audit and Outbox facts.  Fill projection updates the
Core/Tactical inventory and SQL daily-loss authority exactly once.  Binance Income
facts are also projected idempotently before production execution begins.

## Recovery

PREPARED, SUBMITTING, ACKNOWLEDGED, PARTIAL and UNKNOWN orders are recovered from
client-order-id, REST state and independent fill evidence before any resubmission.
Unresolved evidence remains fail-closed.  Position adoption requires a signed manifest
and seeds both execution and inventory projections.

## Safety

Normal production remains LIMIT-only.  Emergency MARKET is available only through a
separate exact-scope, reduce-only, dual-authorized, short-TTL, single-use permit and
still uses the same SQL risk, budget, fencing, lifecycle and fill projection chain.
The legacy R5 write CLI is disabled.
