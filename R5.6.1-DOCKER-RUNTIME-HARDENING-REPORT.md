# Freqtrade-Hedge R5.6.1 Docker Runtime Hardening

## 1. Scope

R5.6.1 applies the Docker installation and Dry-run postmortem findings to the current R5.6.0 source tree. It preserves the R5.6 Dry-run productionization layer and adds reproducible container build, secure configuration bootstrap, network/data-quality qualification, deterministic Hedge-paper proof, seven-layer runtime credibility, and redacted evidence collection.

The release does **not** unlock any exchange write path. Installation and offline diagnostics use no exchange credentials and make no exchange requests.

## 3. Additional defects found during implementation

1. The initial R5.6.1 scripts invoked `python -m freqtrade.hedge.r561.cli`, but the module did not execute `main()`. The command could return success without performing a gate. All scripts now invoke `python -m freqtrade.hedge.r561`, and `cli.py` also has a direct execution guard.
2. A fresh named Docker volume did not contain the configured JSON file. The entrypoint now atomically bootstraps a Docker-specific config with random local API credentials and preserves it on restart.
3. Binding the API to container loopback prevents Docker port forwarding. The Docker template binds inside the container to `0.0.0.0`, while Compose publishes only `127.0.0.1:8080`. Local non-Docker templates remain loopback-only.
4. Dockerfile COPY sources are now parsed and checked during source audit, preventing late build failures from nonexistent paths.

## 5. Runtime credibility levels

| Level | Meaning | Required evidence |
|---:|---|---|
| L1 | Process | Container/worker is running |
| L2 | Exchange | Public exchange initialization completed |
| L3 | Data | Ticker and OHLCV probes pass, candle is fresh, no excess gaps |
| L4 | Strategy | Closed-candle strategy cycles advance and remain fresh |
| L5 | Simulation | Deterministic scenario passed and simulated orders/fills exist |
| L6 | Ledger/recovery | Ledger consistency, reconciliation freshness and restart recovery pass |
| L7 | UI/API | API and Dashboard are healthy; simulation can be called credible |

`RUNNING` alone therefore remains `RUNNING_UNVERIFIED`, not `CREDIBLE`.
